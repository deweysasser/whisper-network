# whisper-network

Distribute [whisper.cpp](https://github.com/ggml-org/whisper.cpp) transcription
across an ad-hoc fleet of machines. One Go binary runs as a coordination
server, as a worker, or as a small client CLI. Any machine that can run a
container or a static binary can join as a worker, with only the server URL
configured.

Status: pre-1.0. The HTTP API and flags may still change. See
[Project status](#project-status).

## Why

Transcribing a large backlog of recordings on one machine takes days to weeks.
whisper-network splits each recording into chunks, hands the chunks to whatever
machines are available, and reassembles the transcript. Clients only speak
HTTP and upload whatever media they have; conversion to Whisper's input format
happens inside the service.

Design points:

- No shared filesystem. Media and results move over HTTP.
- At-least-once processing with fenced leases. A crashed or partitioned worker
  never loses a job and cannot overwrite a result it no longer owns.
- Weighted fair sharing of the fleet across queues, and across job weight
  classes within a queue.
- Workers are untrusted until a human approves them for specific queues.
- ffmpeg runs only inside a sandboxed worker child process, never on the server.
- Clients can submit a media URL instead of an upload. The server never fetches it; separate, sandboxed downloader workers do (see "URL jobs").
- State is one SQLite file plus a blob directory: one volume to back up.
- Logs are JSONL for VictoriaLogs; metrics are Prometheus text, scrapeable or
  pushable.

Non-goals: high availability (one server, one SQLite file), diarization,
translation, engines other than whisper.cpp, downloading video (URL jobs fetch
audio only), push notifications. The full specification is [DESIGN.md](DESIGN.md).

## How it works

```
                       +---------------------- server ----------------------+
  clients  --HTTP-->   | queues, jobs, auth, SQLite + blobs, scheduler,     |
  (API token)          | reaper, /metrics (separate listener), web UI       |
                       +--------------------------+-------------------------+
                                                  ^
                          long-poll claim, heartbeat, upload result
                                                  |
                  +-------------------+-----------+-------+-----------------+
                  |                   |                   |                 |
              worker A            worker B            worker C          worker N
         (prepare+transcribe)  (transcribe only)   (macOS, no sandbox)
```

A job is split into tasks:

1. `prepare` (optional): a worker converts the upload to 16 kHz mono 16-bit
   FLAC with ffmpeg inside a sandbox. Uploads that are already canonical WAV or
   FLAC skip this step.
2. `transcribe` (one or more): the server cuts the canonical audio at quiet
   points into chunks of roughly one hour. A worker runs whisper-cli on one
   chunk, fed a WAV stream generated by the server.

A worker claims one task at a time by long-polling the server. The claim
creates a **lease**: a random ID that expires unless the worker heartbeats
(every 30 s by default; leases live three intervals). The lease ID fences all
later calls. If the lease has expired, was cancelled, or the job was deleted,
the worker gets `410 Gone` and must stop. A task that failed or whose lease
expired on a worker is never given back to that worker; it is retried on
another one, and fails the job only after failing on `--max-attempts`
different workers (default 2), so one bad worker cannot fail a job. A
failure caused by the input (for example media ffmpeg cannot read) fails the
job at once. If no other eligible worker takes a failed task within
`--retry-wait-limit` (default 24h), for example on a single-worker fleet,
the job fails with an error naming the workers that failed it. A failure the
worker reports before starting work (a missing tool or model, a foreign
`input_url`) uses no attempt and does not exclude the worker; it counts only
toward the circuit breaker. When a task fails for good, the job's queued tasks
are cancelled but tasks already running finish and keep their results; the job
becomes `failed` when the last one ends, with an error ending in its progress
(`…; 2 of 12 tasks done, 4 cancelled`). When the last transcribe task
finishes, the server assembles the transcript.

## Trust and security

whisper-network runs untrusted media through native code on machines you may
not fully control, on behalf of callers who should see only their own work.
It is built around a few explicit boundaries. Each one is a decision an
operator makes, and every such decision is written to the audit log.

### The server is the trust anchor

The server holds the database, every credential and all media. It never runs
ffmpeg or any native media parser: uploads that are already canonical WAV or
FLAC are validated by a pure-Go decoder, and everything else is converted on a
worker. Tokens are 256-bit random values, stored only as sha256 hashes and
shown once; user passwords use argon2id. Run it behind TLS
(`--require-tls` refuses to start without it) and keep the metrics listener
private.

### Principals

| Principal | Credential | Can do |
|---|---|---|
| **User** | Password and session cookie (web UI; also the API) | Whatever their grants allow |
| **Client** | `wnc_…` bearer token | Whatever its grants allow: typically submitting to and reading from queues |
| **Worker** | `wnw_…` bearer token | Lease tasks from queues it holds `process` on; nothing else |

Grants are `role=scope`, with scope `*`, `queue:<name>` or `worker:<id>`
(roles table under [Concepts](#concepts)). Nobody can hand out a permission
they don't hold: a client admin creating a client may delegate only grants
it holds itself, and only `admin` grants `read_all` or changes a queue's
share of the fleet.

### Queues are the access boundary

A queue is both a scheduling unit and a wall between tenants.

- **Submitters see their own jobs.** A client with `submit` on a queue
  creates jobs there and sees, reads and deletes only the jobs it created.
  Asking for anyone else's job returns `404`, the same as a job that doesn't
  exist, so job IDs can't be probed.
- **Seeing a job is separate from reading it.** `view_all` (and
  `queue_admin`) lists every job on the queue with its full status, prompt,
  metadata and submitter, but not its transcript. Transcripts and results
  need `read_all`, which only `admin` can grant. A queue administrator runs
  a queue without being able to read what is said in it.
- **Fleet share is an operator decision.** Only `admin` sets a queue's
  weight, so a queue's owner cannot take more of the fleet than they were
  given.

### Workers are untrusted until approved, per queue

Anyone can register a worker, and registering grants nothing: the worker sits
`pending` until an operator acts. Approval is two separate decisions:
`worker_admin` admits the machine, and `queue_admin` on each queue decides
whether it may process that queue's media. A worker never sees jobs, only the
tasks it leases, and it receives media only from queues it holds `process`
on. Revoking that grant cancels its live leases on the queue at once.

An approved worker is trusted with what it processes: it hears the audio of
its queues, and it returns their transcripts. Approve a worker for a queue
only if you would let its operator hear that queue's audio. Within that
trust, the damage a misbehaving worker can do is contained:

- Everything it returns is checked. Converted audio is fully decoded and
  validated on the server, and every call is fenced by its lease, so a stale
  or rogue worker cannot overwrite another's result.
- A failed task is retried on a *different* worker, and a worker that keeps
  failing is paused automatically (the circuit breaker, under
  [Concepts](#concepts)).
- Who processes a job is shown only to operators (`admin`, the queue's
  `queue_admin`, or `worker_admin` over that worker), not to submitters.

### URL jobs: only downloaders fetch

The server never connects to a URL a client names. A client with the
`submit_url` grant posts a URL, and a **downloader** worker (`worker
--downloader`, its own image) fetches it with yt-dlp (or a plain GET for direct
links) and streams the audio back as the job's media. Downloaders are a separate
kind of worker, fixed at registration: they hold the `fetch` grant, never
process media, and processing workers never fetch. Every connection a
downloader makes goes through an address filter that refuses loopback, private,
CGNAT, link-local and similar addresses (unless `--allow-private-egress`), and
yt-dlp runs in a sandbox that may only connect to that filter's proxy port.
The proxy and the plain GET (redirects included) reach only ports 80 and 443.
Residual risk: Landlock limits TCP connects by port, not address, so a
compromised yt-dlp could reach a host listening on the proxy's own port,
bypassing the filter. Close that with an egress firewall on the downloader's
network that lets out only TCP to 80, 443 and the server's port (plus DNS):
the proxy's port is ephemeral and never one of those. A `--yt-dlp-cookies`
file is readable by yt-dlp, so it is what a compromised yt-dlp would steal,
and anyone with `submit_url` fetches with that account's session: use a
throwaway account. See DESIGN.md section 13. A URL is job content: metrics,
the audit log and routine logs carry only the site (`youtube.com`), but a
failed fetch's error and logged stderr are kept in full and may quote it.

### Media is handled in a sandbox

Every ffmpeg, whisper-cli and yt-dlp process runs under `sandbox-exec`: Landlock
filesystem (and, on kernel 6.7+, network) rules, a seccomp filter that
refuses sockets and new namespaces, `no_new_privs`, resource limits, a
timeout, and a dedicated unprivileged UID when the worker runs as root. The
worker tests its own sandbox at startup and reports `full`, `fs-only` or
`none`. Converting untrusted uploads goes only to workers at
`--prepare-min-sandbox` (default `full`); whisper-cli only ever receives WAV
generated by the server.

### Accountability

Every change to permissions, approvals, worker state, clients, users and
queue weights is recorded in the audit log with who made it and when,
including automatic actions such as the circuit breaker's pauses (actor
`system`). Logs never contain tokens, passwords, transcripts or prompts.

See [SECURITY.md](SECURITY.md) for the threat model, the hardening checklist
and how to report a vulnerability, and DESIGN.md sections 5 and 13 for the
full rules.

## Quick start with Docker

Images are published to GitHub Container Registry:

- `ghcr.io/deweysasser/whisper-network:<tag>`: the worker image. It contains
  whisper-cli and ffmpeg and can also run `server`.
- `ghcr.io/deweysasser/whisper-network:<tag>-server`: a minimal distroless
  image with only the server.

Tags: each release tag `vX.Y.Z` publishes that tag; final releases also move
`latest` and `stable`, release candidates (`vX.Y.Z-rc.N`) do not. Pushes to the default branch publish
`br-<branch>` images (for example `br-main`); other branches are built in CI
but never pushed, and a branch can never produce `latest`, `stable` or a `v*`
tag. The server image keeps its data directory `/data` at mode 0700, owned by
uid 65532.

The examples assume `latest`; pin a release tag for anything you intend to keep.

### 1. Start the server

```sh
docker network create wn
docker volume create wn-data
docker run -d --name wn-server --network wn -v wn-data:/data \
    -p 127.0.0.1:8080:8080 \
    ghcr.io/deweysasser/whisper-network:latest-server
```

On first start the server creates a UI user `admin` with a random password and
prints it once to stderr:

```sh
docker logs wn-server 2>&1 | grep -A2 'created user'
```

You must change the password at first login (web UI at `http://127.0.0.1:8080/ui/`).
To choose the password yourself, set `WHISPER_ADMIN_PASSWORD` on the first start.

### 2. Create a client token

Clients are API principals. Create one with permission to submit to the
`public` queue (created at bootstrap). The admin commands open the SQLite
database directly, so run them inside the server container:

```sh
docker exec wn-server whisper-network admin create-client \
    --name my-script --grant submit=queue:public
```

The output includes `token wnc_...`. It is shown once; store it.

### 3. Start a worker

Mount the state volume, otherwise every restart registers a new worker:

```sh
docker volume create wn-worker-state
docker run -d --name wn-worker \
    -v wn-worker-state:/var/lib/whisper-network \
    --cpu-shares 128 --memory 6g \
    --network wn \
    ghcr.io/deweysasser/whisper-network:latest \
    worker --server http://wn-server:8080 --description "my worker"
```

For a worker on another machine, point `--server` at the server's HTTPS URL.

The image runs the worker as an unprivileged user (uid 10001), and ffmpeg,
whisper-cli and (on downloaders) yt-dlp run as that user inside the sandbox. If you run the worker as root
(for example from a binary under systemd), it refuses to start unless you pass
`--child-uid` and `--child-gid`: an unprivileged user and group, dedicated to
whisper-network, that the children switch to. Do not use `nobody` or any uid
another service or container runs as; the worker refuses to start while
anything else runs as that uid, and the children's process limit counts every
process of it.

The worker registers and waits in the `pending` state. It receives no work
until you approve it. Find its ID and approve it for the `public` queue:

```sh
docker exec wn-server whisper-network admin list-workers
docker exec wn-server whisper-network admin approve-worker --id <id> --queue public
```

Approval can also be done in the web UI. The worker polls with backoff (30 s up
to 5 min), so it can take a moment to notice. On first use it downloads the
model it needs from the server, which fetches it from upstream and caches it.

### 4. Submit and fetch

Use the CLI from any machine with the binary (see below), or the container:

```sh
export WHISPER_SERVER=http://127.0.0.1:8080
export WHISPER_TOKEN=wnc_...

id=$(whisper-network submit --queue public --model small.en meeting.mp4)
whisper-network status "$id"
whisper-network fetch "$id" -o meeting.txt
```

`fetch` fails until the job is `done` (`fetch --partial` returns what is
transcribed so far, gaps marked). `status` with no job ID lists the
queue's jobs (`--state` filters). `fetch --json` returns segments with
absolute times. A failed job is retried from the server's copy of the media
with `whisper-network retry "$id"`; nothing needs uploading again.

### 5. Optional: URL jobs with a downloader

Run a downloader from the `-downloader` image (the worker image plus yt-dlp and
deno, without whisper or ffmpeg):

```sh
docker run -d --name wn-downloader -v wn-downloader:/var/lib/whisper-network \
  ghcr.io/deweysasser/whisper-network:latest-downloader \
  worker --downloader --server http://<server>:8080 --description "my downloader"
```

Approve it like a worker, but grant it `fetch` instead of `process`, and give
clients `submit_url` on the queue (the UI's queue page offers both). Then:

```sh
id=$(whisper-network submit --url 'https://example.com/talk.mp3' --model small.en)
```

or `POST /queue/{q}/fetch` with the job params plus `url`. With no eligible
downloader for the queue the server answers `409 no-downloader`. Fetch limits
are per site and per egress address, set by an admin on the **Fetch** page
(`/ui/fetch`) or `/admin/fetch-policies`: the defaults allow YouTube one fetch
per 3 minutes and back off for 12 hours after a rate limit. Downloaders behind
one public address should share `--egress-group NAME` (or set `--egress-probe`)
so they are paced together. Needs a kernel with Landlock ABI 4 (Linux 6.7+):
below that the sandbox cannot let yt-dlp reach the proxy, and the downloader
refuses fetch leases. Lowering `--fetch-min-sandbox` does not help on Linux:
the downloader is then offered fetch leases, refuses each, and is paused by the
server's circuit breaker.

Give the downloader its own network and an egress firewall that allows only
outbound TCP to ports 80, 443 and the server's port, plus DNS. With Docker and
a downloader on bridge network `172.30.0.0/24`, server on 8080:

```sh
iptables -I DOCKER-USER -s 172.30.0.0/24 -j DROP
iptables -I DOCKER-USER -s 172.30.0.0/24 -p udp --dport 53 -j ACCEPT
iptables -I DOCKER-USER -s 172.30.0.0/24 -p tcp -m multiport --dports 53,80,443,8080 -j ACCEPT
iptables -I DOCKER-USER -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT
```

If that network has IPv6 enabled, add the same rules with `ip6tables` for its
IPv6 subnet (here `fd30::/64`):

```sh
ip6tables -I DOCKER-USER -s fd30::/64 -j DROP
ip6tables -I DOCKER-USER -s fd30::/64 -p udp --dport 53 -j ACCEPT
ip6tables -I DOCKER-USER -s fd30::/64 -p tcp -m multiport --dports 53,80,443,8080 -j ACCEPT
ip6tables -I DOCKER-USER -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT
```

That closes the one path around the egress proxy (DESIGN.md section 13).

## Quick start with binaries

Release archives for linux, darwin and windows (amd64 and arm64) are attached
to each GitHub release. Only Linux has been run in a real deployment; the
macOS and Windows builds compile and run the unit tests in CI but are
otherwise untested, and the worker does not run on Windows at all (see
[Project status](#project-status)). Or build from
source (Go version from `go.mod`):

```sh
make            # builds ./whisper-network
```

The server needs nothing but the binary:

```sh
./whisper-network server --data ./data --listen 127.0.0.1:8080
./whisper-network admin create-client --data ./data --name my-script --grant submit=queue:public
```

A worker needs `whisper-cli` (whisper.cpp) and `ffmpeg` on `PATH`, or passed
with `--whisper-cli` and `--ffmpeg`. A worker that sets `--kinds transcribe`
does not need ffmpeg.

```sh
./whisper-network worker --server http://127.0.0.1:8080 --state ./worker-state
./whisper-network admin list-workers --data ./data
./whisper-network admin approve-worker --data ./data --id <id> --queue public
```

Run `whisper-network bench` on a candidate worker to measure realtime factor
and peak memory at several thread counts before choosing `--threads-per-slot`
and `--slots`.

Sandboxing uses Linux Landlock. macOS and Windows workers report sandbox level
`none`; under the default `--prepare-min-sandbox=full` they receive only
transcribe tasks.

## Concepts

**Queues and weights.** A queue is a named set of jobs and an access boundary.
A worker sees media only from queues it is approved for. Each queue has an
integer weight (1 to 10000, default 100, changeable only by `admin`). While
several queues are backlogged, the fleet's time divides in proportion to their
weights; an idle queue's share goes to the others. Scheduling is two-level
start-time fair queueing (DESIGN.md section 8.2).

**Job weight classes.** Within a queue, a job has class `low`, `medium`
(default) or `high`, sharing 1 : 2 : 4 by default (`--class-weights`). Lower
classes are slowed, never starved. Inside a class, jobs run in FIFO order.

**Cost.** A task's scheduling cost is its audio seconds times a per-model factor
(`--model-factors`); a prepare task costs a fixed amount.

**Workers and approval.** Registration (`POST /worker`) is unauthenticated and
grants nothing. A worker is `pending` until an operator approves it. Approving
is two decisions: the worker's lifecycle (`worker_admin`) and its access to each
queue's media (`queue_admin` on every chosen queue). States are `pending`,
`active`, `paused` (finishes running leases, takes no new ones) and `rejected`
(token revoked, terminal). There are no enrollment tokens. A rejected worker is
deleted after `--rejected-worker-retention` (30 days), or at once from its page
(Delete) or the Workers page (Delete all rejected), or with
`DELETE /admin/workers/{id}`; only rejected workers can be deleted, so reject
first. A deleted worker's token is then unknown, and the final work counters are
kept in the `worker.delete` audit entry.

**Circuit breaker.** A worker that keeps failing is paused automatically: after
`--worker-failure-limit` (default 3) failed or expired leases in a row, spanning
at least two jobs, the server pauses it, audits the pause with the actor
`system` and the reason, logs `worker.auto_paused`, and sets
`whisper_worker_auto_paused`. A completed task resets the streak. Failures
caused by the input (ffmpeg rejecting an upload) do not count, and the two-job
rule keeps one bad upload from pausing healthy workers; it does not apply to
failures before work starts, so a misconfigured worker is paused even with one
job queued. The Workers page shows
the reason; resuming the worker clears it. `0` disables the breaker.

**Version skew.** The Workers page shows each worker's whisper-network version
(engine and ffmpeg versions on hover) against the server's own: an older
worker is badged "outdated", a newer one noted "newer than server", and one
that cannot be ordered (a no-tag or dirty build at the same point, an
unrecognised string) marked "differs". Dev builds compare by base version,
then commits since the tag. The dashboard's Fleet versions tile counts workers
per version and flags a fleet running mixed whisper.cpp versions.

**Reading the UI.** Workers, jobs and API clients appear by name (a job by its
label) with a short id after it, each linked to its page; every table column,
details field (a worker's facts and statistics, a job's, queue's or
client's details) and dashboard tile has an ⓘ explaining it. The dashboard's Capacity tile shows task slots in use
and available across the fleet, and per queue. A queue's page summarizes its
pending tasks and says why they are waiting (no eligible worker, no worker
with the model, prepare needing a full sandbox, the only able worker already
failed it, all slots busy); the job page lists every waiting task with its
wait, attempts and last failure.

**Sandbox levels.** Every ffmpeg, whisper-cli and yt-dlp child runs under
`whisper-network sandbox-exec`, which applies lowest CPU and I/O priority,
`no_new_privs`, resource limits and Landlock filesystem rules, and (kernel 6.7
or later) Landlock TCP restrictions. The worker self-tests at startup and
reports `full`, `fs-only` or `none`. `--prepare-min-sandbox` on the server
decides which levels may receive prepare tasks (ffmpeg on untrusted media);
transcribe tasks go to any level because their input is server-generated WAV.

**Roles.** Grants are `role=scope` with scope `*`, `queue:<name>` or
`worker:<id>`. Details: DESIGN.md section 5.

| Role | Scope | Allows |
|---|---|---|
| `admin` | `*` | Everything |
| `queue_admin` | `queue:X` | Approve workers for X; grant `submit`, `submit_url`, `view_all`, `delete_all`, `process`, `fetch` on X; list jobs and read their full status; delete any job. Not transcripts |
| `worker_admin` | `*` or `worker:<id>` | Approve, pause, resume, reject and delete (once rejected) workers |
| `client_admin` | `*` | Create and revoke API clients |
| `submit` | `queue:X` | Create jobs; see, read and delete its own |
| `submit_url` | `queue:X` | Create URL jobs (a downloader fetches the media); the same own-job rights as `submit` |
| `view_all` | `queue:X` | List every job and read its full status, including prompt, metadata and submitter (not the transcript or result) |
| `read_all` | `queue:X` | Read every job's transcript and result; implies `view_all`. Granted by admin only |
| `delete_all` | `queue:X` | Delete any job |
| `process` | `queue:X` | Processing workers: lease prepare and transcribe tasks from X |
| `fetch` | `queue:X` | Downloader workers: lease fetch tasks from X |

Upgrading from a release without `read_all` gives every existing `view_all` and
`queue_admin` grant a matching `read_all` grant, so access is unchanged until
you revoke them.

## API overview

Every server also serves **`/llms.txt`**, a Markdown guide to the client API
(submit, poll, fetch, clean up, errors) written for LLM agents and filled in
with that server's models, upload limit and retention. Point an agent at
`https://<your-server>/llms.txt`. It is public and contains no queue names,
tokens or worker details.

All bodies are JSON unless noted; errors are RFC 9457 `application/problem+json`.
Client tokens (`wnc_...`) and worker tokens (`wnw_...`) go in
`Authorization: Bearer`. Full request and response shapes are in
[DESIGN.md section 6](DESIGN.md#6-http-api).

| Method and path | Purpose | Caller |
|---|---|---|
| `POST /queue/{q}` | Create a job (multipart: `params` JSON, `media`); honours `Idempotency-Key` | client |
| `GET /queue/{q}` | List visible jobs (`state`, `since`, `limit`, `cursor`; `sort=state`, or `sort=created&order=asc\|desc`) | client |
| `POST /queue/{q}/fetch` | Create a URL job (JSON: job params plus `url`); honours `Idempotency-Key`; `409 no-downloader` without an eligible downloader | client (`submit_url`) |
| `POST /queue/{q}/bulk` | Retry or delete many jobs: `{"action":"retry"\|"delete", "job_ids":[...]}` or `"filter":{"state","since","cursor"}`, optional `"dry_run"`; at most 500 per request; per-job outcomes | client (authorized per job) |
| `PATCH /queue/{q}` | Change weight, description, upload cap | admin / queue_admin |
| `GET /job/{id}` | Job status | client |
| `GET /job/{id}/transcript` | Text transcript with provenance header; `?partial=1` for a failed or unfinished job's transcript so far, gaps marked | client |
| `GET /job/{id}/result` | JSON segments, absolute times (also `?partial=1`) | client |
| `POST /job/{id}/retry` | Retry a failed job: done tasks kept, the rest re-run from the retained media; `409 not-retryable` once purged | owner, queue_admin, admin |
| `DELETE /job/{id}` | Delete job and blobs | client |
| `POST /client`, `GET /client/{id}`, `DELETE /client/{id}` | Manage client tokens | client_admin |
| `POST /worker`, `GET/PATCH /worker/{id}` | Register; read or update own facts | worker |
| `POST /worker/{id}/leases?wait=` | Claim a task (long poll) | worker |
| `POST /worker/{id}/gauges` | Report gauges without claiming (a worker whose host is busy) | worker |
| `GET /lease/{id}/input` | Task input | worker |
| `POST /lease/{id}/heartbeat`, `PUT /lease/{id}/result`, `POST /lease/{id}/failure`, `DELETE /lease/{id}` | Lease lifecycle | worker |
| `GET /models/{name}` | Pinned model file | worker |
| `/admin/...` | Workers, queues, users, clients, grants, audit; `fetch-policies` and `fetch-cooldowns` (per-site fetch limits, admin only) | user or client with admin roles |
| `GET /admin/version` | The server's own version, `{"version":"v0.5.0"}`, to compare with workers' `facts.version` in `GET /admin/workers` | admin, worker_admin, queue_admin |
| `GET /healthz`, `GET /readyz` | Liveness, readiness | none |
| `/ui/` | Web UI | user |

The admin endpoints are listed in the header comment of
`internal/server/admin.go`.

## Configuration reference

Every flag has a `WHISPER_*` environment variable; flags override the
environment. There is no config file. Run `whisper-network <command> --help`
for the authoritative list.

### Common flags (all commands)

| Flag | Default | Env | Description |
|---|---|---|---|
| `--debug` | off | `WHISPER_DEBUG` | Debug logging |
| `--quiet` | off | `WHISPER_QUIET` | Warnings and errors only |
| `--output-format` | `auto` | `WHISPER_OUTPUT_FORMAT` | `auto`, `terminal` or `jsonl`. `auto` is human-readable on a TTY and JSONL otherwise |

### `server`

### Client commands: `submit`, `status`, `fetch`, `retry`, `delete`

All of them take `--server` (`WHISPER_SERVER`) and `--token` (`WHISPER_TOKEN`).

| Command | Flags |
|---|---|
| `submit <file>` or `submit --url <url>` | `--url` (a media URL for a downloader to fetch instead of a file; needs `submit_url`), `--queue` (`public`), `--model` (`small.en`), `--language` (server default `en`; `auto` allowed), `--weight` (`low`, `medium`, `high`), `--prompt` (at most 800 characters), `--label`, `--source` (recorded, never fetched; defaults to the URL with `--url`), `--metadata` (JSON object), `--idempotency-key`, `--json` (print the job document instead of its ID) |

## Observability

### Logs

Every process writes one JSON object per line to stdout, using VictoriaLogs'
default field names, so no field mapping is needed:

| Field | Content |
|---|---|
| `_time` | RFC 3339 timestamp, UTC |
| `_msg` | Short human message |
| `level` | `debug`, `info`, `warn`, `error` |
| `service`, `mode`, `version`, `host` | `whisper-network`; `server`, `worker` or `admin`; build version; hostname |
| `event` | Stable dotted name such as `job.created`, `task.leased`, `lease.expired` (catalog in DESIGN.md section 10.1) |
| `job_id`, `lease_id`, `worker_id`, `queue`, ... | Flat event fields, consistent across server and worker |

Tokens, passwords, cookies, prompts, transcript text and job metadata are never
logged.

Ship stdout with a collector (vlagent, Vector, Fluent Bit, a Docker log driver)
and set the stream fields at ingestion:

```
POST /insert/jsonline?_stream_fields=service,mode,host
```

(or the `VL-Stream-Fields: service,mode,host` header). `service`, `mode` and
`host` are low-cardinality. Never make `job_id`, `lease_id` or `worker_id`
stream fields. `deploy/vector.yaml` is a working Vector configuration.

If the first-run admin password banner is written to stderr, make sure your
collector does not ship it (the example configuration drops non-JSON lines).

### Metrics

The server serves Prometheus text format at `/metrics` on the metrics listener
(`--metrics-listen`, default `127.0.0.1:9090`, loopback only), which is separate
from the API port. To let a scraper reach it, bind a private interface
explicitly (in a container, `:9090` on a network that is not published). It can also push to VictoriaMetrics with
`--metrics-push-url`, `--metrics-push-interval` and `--metrics-labels`.

Workers need no metrics configuration: the server derives fleet metrics from the
protocol and re-exports a few worker gauges from heartbeats with a `worker`
label. A worker can additionally expose `--metrics-listen` or push with
`--metrics-push-url` for host-level detail.

Key series: `whisper_jobs`, `whisper_tasks`, `whisper_queue_backlog_cost`,
`whisper_queue_oldest_pending_seconds`, `whisper_queue_eligible_workers`,
`whisper_fleet_slots{state,kind}` (slots in use, available, deferred, paused),
`whisper_sched_served_cost_total`, `whisper_leases_ended_total`,
`whisper_workers`, `whisper_worker_last_seen_timestamp_seconds`,
`whisper_worker_info` (labels include `version`, `engine_version`),
`whisper_server_info{version}`,
`whisper_worker_slots_busy`, `whisper_task_realtime_factor`,
`whisper_fetch_total{site,outcome}`, `whisper_fetch_bytes_total{site}`,
`whisper_fetch_cooldowns`, `whisper_fetch_blocked_tasks`,
`whisper_fetch_invalid_policies`,
`whisper_data_free_bytes`, `whisper_storage_bytes` (`kind="failed"`: media held
for failed jobs), `whisper_failed_jobs_retryable`.

Never label by job, lease or client. `route` labels use the route pattern, not
the raw path.

### Alerts

[deploy/alerts.yml](deploy/alerts.yml) holds vmalert/Prometheus rules: server
not scraped, queue stalled, lease churn, worker vanished, worker auto-paused by
the circuit breaker, low disk (server data directory and worker state
directories), and pending tasks with no eligible worker. Load it into vmalert
or Prometheus as-is.

### Health

`GET /healthz` (process up) and `GET /readyz` (database writable, enough free
space), unauthenticated, on the API listener.

## Security model

The server holds every secret and the database, so it never runs ffmpeg or any
native media parser: WAV and FLAC are validated and encoded in pure Go. Media
conversion runs in a sandboxed worker child process. Workers are untrusted until
approved per queue, tokens are stored only as sha256 hashes, and leases fence
stale workers. Run behind TLS; keep the metrics listener private. See
[SECURITY.md](SECURITY.md) for the threat model, the hardening checklist and how
to report a vulnerability.

## Building and testing

```sh
make                 # build ./whisper-network
make vet             # go vet ./...
make test            # go test ./...
make test-race       # go test -race ./...
make cover           # coverage summary
make fuzz            # short fuzz pass over the WAV, FLAC and token parsers
make integration     # end-to-end stack test (needs Docker; slow)
make image           # worker image (also runs `server`)
make image-server    # server-only distroless image
make tools           # install staticcheck, gocritic, gosec
```

Tests that run on real time (the end-to-end harness, worker and server long
polls) scale their lease TTLs, heartbeat intervals and deadlines by
`WN_TEST_TIME_SCALE` (default 1, doubled under `-race`). Raise it on a slow
or heavily shared machine, e.g. `WN_TEST_TIME_SCALE=3 make test-race`.

The build system follows the [golang-program template](README-TEMPLATE.md).
See [CONTRIBUTING.md](CONTRIBUTING.md) for development workflow.

## Project status

Pre-1.0. Expect breaking changes to flags and the HTTP API between releases;
changes are described in the release notes. There is one server and one SQLite
database per deployment; high availability is a non-goal. Open design questions
are in DESIGN.md section 14.

Platform support:

| Platform | Status |
|---|---|
| Linux, amd64 and arm64 (containers or binaries) | Developed and run on Linux; the real-engine integration test (ffmpeg and whisper.cpp in Docker) passes |
| macOS (darwin) | **Never run outside CI.** Binaries are built and the unit tests run on GitHub's macOS runners; no real worker or server has been operated on a Mac. No sandbox (level `none`), so no prepare tasks under the default policy |
| Windows | **Worker not supported**: `whisper-network worker` exits with an error, because the media tools it runs cannot be confined there ([#26](https://github.com/deweysasser/whisper-network/issues/26)). The server and the client CLI (`submit`, `status`, `fetch`) build and pass their unit tests on GitHub's Windows runners but have **never been run outside CI** |

Reports from macOS or Windows use are welcome.
